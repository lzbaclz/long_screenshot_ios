# Beta 6 接缝选址：开发与验收流程

日期：2026-09-15。当前状态：最终生产源码已通过本地验收，0.1.5（6）已手动上传并开放内部 TestFlight。

依据用户提供的 [App 资源库接缝设计](../beta-6-app-library-seam-plan.md)，目标为 0.1.5（6）。实现由两条 GPT-6-Astra high 开发线完成，主 agent 负责原图核对、接口审查、验收执行和发布控制。所有记录使用 Markdown；不新增 CI 或上传自动化。

## 本轮范围

完成自动接缝选址、正文条带的原子替换、实际提交诊断和回归验证。可选的接缝余量与编辑器拖动作为下一步，不在本轮实现。

1. **独立核对用户证据。** 已找到 884×2380 的原尺寸导出文件并查看全分辨率接缝，重跑既有分析脚本。主要高相关图标段偏移约 335–337；低相关窗口存在错配，因此不能据此宣称全图逐像素无缺失。原始捕捉帧和清单缺失，一次上翻、847 行接缝及 387+460 分段仍是结构推断。
2. **先审查选址与来源契约。** 像素误差最小可能在不透明图标内部；选择要兼顾图像结构和局部平稳性。旧头尾边缘不能默认当作可移动正文，否则可能重新带入固定栏。
3. **核心开发线。** 提供独立 `SeamSelector`，比较已经对齐的真实保留正文边缘与新帧，不修改 `StreamStitcher` 的位移、歧义门槛或原始新增行契约。核心冻结后继续开发玻璃网格与真实模拟器手势测试。
4. **存储／采集开发线。** 在提交事务中从实际清单拼出有界正文边缘，选择切口，扩展新条带并裁掉相邻旧正文。首尾不参与替换，用户编辑独立；新增不可变文件与新清单先成功，再删除旧文件。同步补实际提交诊断、原生测试与文档。
5. **主 agent 验收。** 失败交回对应开发线，不能通过放宽旧对齐门槛、跳过真实匹配或修改独立真值让测试通过。发布仅使用通过验收后冻结的生产源码。

## 必须保持的约束

- 输出覆盖范围、自然行序和总高度不变；每一行必须来自真实捕捉帧，不混合、不重画。
- 选址使用实际已保留的合成正文边缘，不能把最近的某张匹配参考当成输出边界；覆盖反转、历史淘汰和多个小旧条带。
- 仅在已确认正文重叠内单侧替换，最多 480 行及真实重叠的 35%；实际读入最多 486 行含上下文。固定首尾不作为余量。
- 完全一致、无合适位置、收益不足、证据不可用、用户编辑、手动来源不足或额度边界等情况保持默认。写入版本冲突必须保留磁盘已发布内容。
- 自动替换不借用用户 `seamTrimPixels`；不能影响高度预算、用户编辑坐标或产生零高度条带。
- 诊断记录实际提交结果，位置明确为各次来源帧原图行号；明细有界，省略数量可见。存储失败不发布“已应用”的记录。

## 验收发现与处理记录

首轮原生执行 92 项，91 项通过；向上加反转用例出现 3 个断言失败。关闭和开启选缝分别重放同一组原始帧，输出均为 3091 行，独立轨迹期望为 2964 行。逐步清单证明首尾高度不变，错误来自第二次 102 行移动被原 pipeline 接受成 229 行，并非新正文替换增高。

使用精确 HEAD `760570d` 核心的隔离重放再次复现。该提交仅记录用户的后台图标关联，不包含本轮选缝源码。重复图标的真实位移票数较少，被既有 top-8 候选截断；原精评器若收到真实候选，其误差反而明显更小。证据保存在 `.work/beta6-validation/legacy-alias/`。这条失败和原高度期望保留，不更换夹具隐藏问题；本轮增加有界候选提出修复的独立审查，不放宽误差或歧义门槛。

真实模拟器玻璃路线也暴露了拒绝及范围不足，尚未通过验收。测试改为汇总失败后继续保存接缝报告、原截图、导出和独立像素检查结果；路线、断言及真值未放宽。所有失败须查清后再回填最终结果，未以纯评分器或既有回归通过替代完整路径。

后续逐帧复核确认第二个独立问题：完整帧可以确认固定纹理及正确 ±450 行移动，缩小正文 ROI 后再重放却失去纹理证据；漏掉连续小步后才出现大间隔的重复图标错误。最终把固定层证据范围与正文运动范围分开：仅自动前景捕捉明确传入原允许范围，每一帧对重新验证；特征、位移评分、重叠和输出仍在正文 ROI，手动范围不扩大。四组原始灰度回放恢复连续 40 次正确滚动。详见本机 `glass-readonly-replay/diagnosis.md`。

恢复完整捕捉后，暗色向下路线另有两次切口进入低对比卡片。最终保留强梯度 ≥8 的判据，并要求同一帧内的弱梯度 ≥3 且二阶局部差 ≥3 才补充计作结构；再把两帧各自的结构证据合并。避免把一帧的平滑坡度与另一帧的量化噪声拼成不存在的边界。没有采用绝对亮度门。固定背景的纯色条带可能与多张来源帧逐字节相同，因此来源 oracle 要求同一个候选同时满足独立文档坐标与原像素，而不是选第一个像素相同的候选；原 ±2 像素容差、整段像素相等及固定栏排除条件不变。

最终确认：核心 108 / 108、确定性基准 217 / 217（8,776 帧）、Release 原生 92 / 92；真实玻璃 UI 4 / 4、既有固定栏／壁纸 6 / 6、中英文明细 UI 1 / 1、PNG／JPEG 保存分享 1 / 1，均无跳过。四条玻璃路线的 40 处接缝中，默认跨卡片 30 处，实际跨卡片 0 处；每图高度 7122、零拒绝、图标顺序与来源像素通过独立检查。Release 模拟器原生测试用于检查优化构建，不代表物理手机资源验收；开启选缝额外读取、重写原 PNG 会增加提交成本，不能只凭复用 CIContext 宣称已经提速。

最终证据为 `.work/beta6-validation/` 内的 `unit-accepted.xcresult`、`glass-accepted.xcresult`、`old-capture-accepted.xcresult`、`seam-details-ui-retry.xcresult`、`save-share-accepted.xcresult`，以及相邻 `*-summary.json`。原始失败结果完整保留。实际原生命令采用 `xcodebuild test-without-building -configuration Release -only-testing:ScrollCaptureTests`；玻璃与既有路线分别选择 `GlassSeamSimulatorCaptureTests` 和 `HeaderSimulatorCaptureTests`／`WallpaperSimulatorCaptureTests`；完整参数见各同名 `.log` 的命令首部。所有构建仅指定本机 `DEVELOPER_DIR`，未改全局 Xcode 或运行云端 CI。发布状态、签名与产物记录统一见 [0.1.5 更新记录](../release/0.1.5-testflight.md)。

真实微信／App 资源库、ReplayKit 时机、手机内存与耗时另行验证。选址只能降低接缝显眼程度，不能保证所有固定背景连续，也不能补出未采集内容；不将系统滚动毛玻璃改成应用修复目标。
