# 流式长截图对齐核心

当前核心支持向页面顶部或更早内容滚动，也支持向页面底部滚动；两端新增内容按自然阅读顺序组成长图。双向拼接、稀疏文字评分和确定性合成基准已完成本地验证。本文不代表微信朋友圈、ReplayKit 真机捕捉、真实字体缩放或设备性能门槛已经通过；各类验收结果分别记录在 [实施状态](implementation-status.md)。

## 输入、坐标与输出契约

`ScrollCaptureCore` 是仅依赖 Foundation 的 Swift Package。系统授权后的捕捉层直接处理屏幕帧，用户手动滚动；核心不录制视频，不访问文件或网络。输入 `GrayFrame` 是紧密排列、按从上到下行序存储的 8 位灰度像素。

iOS 捕捉层仅缩小横向，保留原始图像高度。因此 `topInset`、`bottomInset`、位移和 `sourceRows` 都以原始图像行数计量，写彩色条带时不需要把一个分析行放大成多行。横向缩小和颜色转换仍可能损失文字细节，不能仅凭坐标精度保证真实接缝正确。

```swift
var stitcher = StreamStitcher(
    configuration: AlignmentConfiguration(topInset: 18, bottomInset: 24)
)
let frame = try GrayFrame(width: analysisWidth, height: originalHeight, pixels: grayscale)
let decision = stitcher.ingest(frame)
if let rows = decision.sourceRows {
    switch decision.placement {
    case .append:
        // 将本帧 rows 裁出的条带加到已捕捉正文末尾。
        break
    case .prepend:
        // 将本帧 rows 裁出的条带加到已捕捉正文开头。
        // 条带内部仍为从上到下的行序，不能翻转像素。
        break
    }
}
```

首个可信视口建立坐标原点。设裁剪后正文高度为 `H`：

- `contentOffset` 是当前可信视口相对首个视口的位置。
- `earliestOffset` 是所有已接收视口的最小位置；向起点之前滚动时为负数。
- `furthestOffset` 是所有已接收视口的最大位置。
- 已捕捉正文对应连续区间 `earliestOffset..<(furthestOffset + H)`，高度为 `H + furthestOffset - earliestOffset`。

| `status` | 语义 | `sourceRows` 与 `placement` |
| --- | --- | --- |
| `started` | 首帧建立原点 | 整个配置区域，`.append` |
| `advanced` | 扩展已捕捉区间的任一端 | 更早内容取本帧正文头部行、`.prepend`；更晚内容取正文尾部行、`.append` |
| `unchanged` | 位置没有变化，或裁剪区像素完全相同 | 无新行 |
| `backtracked` | 移动到已覆盖区间内，包括反向后再次前进 | 无新行 |
| `rejected` | 重叠不足、匹配歧义、尺寸变化或配置错误 | 无新行，保留此前位置、边界及可信参考 |

`sourceRows == nil` 时不得写入条带，此时 `placement` 默认为 `.append`，没有实际插入含义。`StitchDecision` 的公开初始化器为新增的 `placement` 和 `earliestOffset` 提供默认值；实际接收结果必须读取这两个字段，不能把所有 `.advanced` 都当作尾部追加。`reset()` 清空参考及三个偏移值。

例如正文高度为 160，首帧从文档位置 600 开始，后续依次访问 563、526、563、600、637。输出先向头部扩展两次，再在已有范围内移动，最后向尾部扩展；结果应逐行等于原始文档 `[526, 797)`，没有重复行，也不会因回到起点而重置。

## 固定壁纸与移动消息

照片壁纸固定在屏幕坐标中、消息气泡独立滚动时，整幅画面不是一个平移平面。0.1.3 为这一实际失败模型加入 `ForegroundMotionRegistration`，由启动探测和连续匹配共享。

先寻找在同一屏幕位置保持稳定、横向和纵向分布充分的二维纹理，过滤重复网格等伪静止证据。壁纸无需占据画面的大部分面积，气泡和图片的遮挡不应直接排除固定层。随后只在发生变化的位置提取有限数量的局部特征，用可区分的图案提出位移候选，再检查两张图中的局部误差、支持范围和不同位移的竞争。重复头像、单个动画、细滚动条和大片相同背景不能单独授权新增内容。

前景候选保留票数最高的 8 个峰及其 ±1 邻域，再补最多 8 个相互分散的峰；两组并集最多 48 个位移进入原有局部验证。这样，同一重复图案的相邻量化肩峰不会用完全部探索机会，原先的一像素竞争解释也不会被删除。该补充来自玻璃重复图标回归：原候选截断曾漏掉更低误差的真实位移。票数仍只用于提出候选，最终误差、支持范围与歧义门槛不变；不保证任意周期内容都可定位。

自动前景起拼另显式保留原允许的静止纹理证据范围：`stationaryEvidenceRows` 可供同一帧对重新判断固定背景，运动特征、位移验证和重叠仍严格限制在已选择的正文 ROI。这样，缩窄正文匹配窗口不会顺带删除判定固定层所需的上下文。该参数默认 nil，沿用同一 ROI；仅自动候选已确认是前景时传原允许范围，手动区域保持隔离。它不是记住“曾经是壁纸”后永久放行，每一帧对仍需重新满足固定纹理条件；固定栏不参与正文运动证明或新增正文输出。

有可信前景位移时，固定壁纸的零位移或单行近似匹配不能覆盖它。无可靠运动证据时，不写条带，也不把未经验证的帧放进连续参考。普通整页平移仍使用下述原匹配方式；新分支必须保留文章、朋友圈、表格、加载动画等已有回归行为。

前景匹配只决定位置和取哪些原始行，不生成图片内容。固定壁纸本身无法同时遵守消息的纵向坐标，因此原始条带连接处可能出现壁纸接缝；消息与图片必须按自然坐标连续保存，不能通过重画背景掩盖缺失或重复。

## 整页平移与稀疏文字评分

1. 仅比较配置的正文区域。若与最近可信参考的正文像素完全相同，直接返回 `.unchanged`。相同的空白或周期画面不能证明存在不可见滚动。
2. 对每张保留的可信参考搜索正、负整数位移。默认至少保留 40% 正文重叠；粗搜索跳过部分空间采样点，但不跳过位移值，以保留奇数像素和单行位移精度。
3. 粗评分最多采样 16 列、24 行；每张参考中误差最小的 12 个候选再用最多 48 列、96 行细评估。采样行成上下镜像对，避免单侧取整遗漏稀疏文字。细节列的同等预算分配在两行的真实信息区间内，原始误差仍在整行采样。
4. 同时比较原始采样像素和有水平局部细节的像素。白底稀疏文字的大量相同背景不会稀释字形错位证据。两类行误差各自结合完整均值与去掉最高约 15% 行误差后的均值，再按原始误差 35%、细节误差 65% 合成。没有细节时只保留原始误差评分，但不能据此绕过后续证据要求。
5. 默认最佳误差须不超过 15，且相对不同位置的第二种解释至少领先 2。即使只差一行也视为不同解释；来自多张参考的同一绝对位置不互相构成歧义。
6. 最佳候选还必须具备分布足够广的细节证据，才可更新可信状态。拒绝帧不会进入参考历史。默认保留 3 张参考，`maxHistory` 可配置为 1 至 8。

细节筛选使用像素与其左右相邻像素的灰度差，阈值为 16。细节评分避开左右各约 `width / 24` 的窄边缘；原始评分及输出像素并未因此裁掉这些列。每行至少需要多于 4 个细节点，并具备宽范围支持或分开的水平结构；窄消息无需横跨整屏六分之一。仅有两条平直边的加载矩形和单根细条不能构成有效结构。候选仍须有至少 4 个双方共同支持的采样行，纵向跨度至少覆盖重叠高度的四分之一，且满足原有误差和歧义门槛。

每张参考缓存每行的可选细节区间，随参考历史回收，不缓存整段视频。细节误差保留一侧有字、另一侧空白的错配处罚，不能让错位候选借白底获得低分。真实中文单、双字消息的回归曾证明旧“整屏六分之一”要求在信息跨度只有 16 个分析像素时不可达到；新方案将预算放在头像和字形上，并检查左右两侧、交替消息、少量噪声、周期消息及位于画面内部的非周期长细条。

本轮稀疏文字回归使用 8 像素高字形、43 像素行距和大片白底，旧评分曾拒绝正确的向上位移。修复增加了有效内容的证据权重，没有降低重叠、最大误差或歧义阈值。同时保留陌生稀疏页面共享白底、周期纹理、空白重叠及孤立移动标志的拒绝测试。

`confidence` 是误差质量与候选分离程度组合得到的 0 至 1 启发式分数，不是经真实数据校准的成功概率。算法仍可能在细节过少或布局相似时保守拒绝。

## 自动匹配区域与原始首尾

`StreamStitcher` 只负责给定区域的对齐。上下手动忽略比例均为零时，iOS 采集层自动寻找用于匹配的内部区域；任何非零手动设置都覆盖自动判断。

启动时先检查固定壁纸下的前景位移；若存在可信前景，由它提供内部匹配范围并重放首帧和当前帧。普通页面再使用多个重叠内部区域估计首次位移，允许向上或向下。只有得到可验证的位移，才比较边缘的“保持原位置”和“随正文平移”两种解释。明确固定边界优先；遇到白色留白、时钟变化等情况时，可提出内部匹配候选，但候选必须把首帧和当前帧重新送入最终区域的对齐器，并得到一致位移。

0.1.4 增加固定结构带，防止同色状态栏／导航栏中的空白在录屏胶囊或时钟改变时被当成移动证据。`FixedRegionDetector.fixedStructureBand(reference:current:)` 在同一屏幕行比较两帧共享的横向结构：梯度至少 16、双方像素差不超过 3 的共同结构列须多于 4 个，且至少占任一帧有结构列的 60%。从上下边缘分别链式扫描，允许最多 `max(12, height / 12)` 行的结构间隔，扫描上限为 30% 帧高加一个支持窗口。返回排他距离，整页匹配区域的上下 inset 都必须达到对应带端。判定对两帧对调保持对称，不依赖哪张画面先出现胶囊。

精确边界若落在结构带内部，`resolve` 返回不确定；边缘移动证据只在带外收集，内部候选和两行边界回退也不能越过带端。带外仍保留原移动行规则，不额外要求留白两侧必须同时出现字形。过度扩大 inset 会缩小实际匹配窗口，曾使朋友圈最早一帧出现歧义；因此没有改变现有位移、误差和歧义门槛来换取通过。

`candidateSet` 返回 `CandidateSet(insets:source:)`，以 `.wholePage`／`.foreground` 明确区域来源，原 `candidates` 兼容接口只返回 insets。负位移会对调两帧后再次识别前景；因此调用方的 `preferredInsets == nil` **不能**证明候选属于整页路径。`CaptureFramePipeline.verifyStart` 对实际 `.wholePage` 候选，在重放前再独立检查 `top >= band.top && bottom >= band.bottom`。真实前景提供的 preferred 区域、以及候选内部新识别的 `.foreground` 区域均豁免；壁纸在气泡间暴露的静止纹理不能成为固定栏约束。前景已识别但被拒绝时返回前景来源的空候选集，不降级为整页猜测。

聊天输入栏、键盘和大块图片可能让上下两端没有移动特征。0.1.2 增加上部正文的非对称探测窗口，允许分布充分的内部运动特征提出候选；固定键盘的静止纹理不能充当运动证据。原始探测位移先通过候选区域重放，才参与一致性判断。一个静止局部不再把所有其它区域的变化当作静止。自动总高度预算使用完整视口高度乘屏数，扣除保留首尾后作为正文预算，不因匹配窗口较窄而提早耗尽屏数。

自动候选表示“这部分可用于匹配”，不表示外围像素可以删除。采集与存储层保留原始画面的首尾各一份：向下扩展时替换尾部边缘，向上扩展时替换头部边缘，已覆盖范围内的移动不重复写入。边缘与相邻新正文作为同一存储事务提交。这样，即使内部匹配区域避开了真实正文留白，留白仍可保留在完整输出中。用户明确设置的手动裁剪则按其指定区域输出。

诊断只记录最终获采用并成功生成首批条带的匹配区域：`matchingTopInset`、`matchingBottomInset`、`matchingFrameHeight` 和 `matchingRegionSource`。`fixedBandTop`／`fixedBandBottom` 保存该次整页起拼复核使用的带端，后续被拒绝的帧不会覆盖它们。所有距离和帧高均为原始图像像素；手动区域与壁纸前景不使用保护带，其字段为 nil，详情显示“不适用”。未采用区域、旧 schema-1 记录缺字段时显示“未记录”，不能把 nil 显示成 0。这些数值描述匹配用途，不授权删除输出首尾。

自动边界不确定时保持候选并等待后续帧，不能仅因一次区域警告就结束系统捕捉。成功开始拼接后的暂时拒绝也保留原可信参考，在有限恢复窗口内继续寻找连续重叠；等待本身不构成补接依据。仍未恢复时只能保留已确认的连续部分，并明确说明中断原因。等待时限属于采集策略，不是核心匹配阈值。

启动候选、首次提交确认和中断恢复属于采集与存储层的持久化契约：候选单屏及其恢复记录应保存在 App Group 共享存储中，成功发布首段后才释放其回退责任；未确认连续滚动时，单屏必须与连续长图分别标记。起拼前的新场景须连续多帧彼此稳定，才能带警告重定起点；持续变化的匹配失败不是新起点的证据。恢复后等待重叠时禁止重定起点。

ReplayKit 的 Pause 和 Finished 是独立事件。暂停只保存状态并冻结计时，保留有限参考与会话租约，不调用结束接口。Resume 后先验证旧参考的重叠；未能衔接的间隔不能跳过。未验证内容仍存在时，即使收到手动／系统结束也保存为部分结果。触发结束的原因和随后写盘错误分别记录，不能用后者覆盖已知的系统／手动触发原因。上述路径有状态与真实生产 pipeline 的本地集成测试，不能由核心基准代替，也不代表实际手机回调序列已经全部验收。

自动起步受内部探测区域和边缘证据共同限制，不能把核心的 40% 最小重叠直接换算成通用的首滑距离。透明导航栏、动态布局、过大初始滑动和白色固定栏与正文留白的混淆，仍可能需要减小滚动步长或手动设置区域。开始拼接后不自动改变既定区域。

## 已确认重叠中的接缝选址

0.1.5 在位移被接受后，为固定背景上的半透明卡片选择更平稳的接缝。`SeamSelector` 是纯评分器：输入是同一文档区间的两个灰度 patch，不估位移、不修改匹配区域、不放宽原对齐门槛。普通页面重叠完全相同或仅有很小量化差异时保留默认缝。

仓库事务从实际保留的 `updated.strips` 正文边缘读取旧 patch；它可以跨多个小条带及此前裁过的条带。匹配器最近的 reference 在历史淘汰或反转后未必等于输出边缘，不能替代实际旧像素。固定首尾 caps 不进入 patch；首次起拼前面刚编码的 initial body 可以在同一事务中参与选址。incoming patch 由已验证的新增行范围映射到相同文档位置。

评分结合像素平均绝对误差、横向结构占用及邻行活动，候选还需具备平稳邻域。不透明图标内部可能 MAE 很低，却不是好的切割位置；移到空隙后原始 MAE 可能上升，综合结构代价下降。默认已平稳、收益不足、差异只有量化量级或没有安全候选时保持默认；不能把综合代价描述为“最小原始差异”或经过校准的视觉质量分数。

最终结构占用保留强边缘，同时识别低对比暗玻璃。对每一帧分别计算横向一阶差 `D = max(abs(center-left), abs(center-right))` 和二阶差 `C = abs(2*center-left-right)`，结构条件为 `D_A >= 8 || D_B >= 8 || (D_A >= 3 && C_A >= 3) || (D_B >= 3 && C_B >= 3)`。弱条件必须在**同一帧同时成立**，之后才对两帧取 OR；不能用 A 帧平滑坡度与 B 帧噪声曲率凑出一条不存在的边缘。相邻 ±1 量化噪声的一阶差不超过 2；平滑渐变通常缺少足够二阶差。该规则对像素反相和未裁断的整体亮度平移保持一致，没有采用绝对亮度自适应门。候选仍要求 6 行邻域中的结构占用不超过 2%、纵向活动不超过 2.5；综合改善须达到原 8 分及 15% 门槛，搜索预算不变。

选址只向已确认旧正文内移动。prepend 扩大新条带并裁旧正文顶部相同的 s 行，append 对称裁旧正文底部；s 非负，上限为 480 原图行、实际重叠的 35% 及加载区间的安全上限三者的最小值。最多读取 486 行 patch，真实重叠长度另传评分器。输出顺序、覆盖区间和总高度不变，只调整原始行来自哪一帧；不混合、重画背景或借用 cap。

裁过的剩余正文编码为新 ID 的 immutable PNG，完整消耗的小条带移出清单，不留下零高度条带。新文件全部写好后原子发布清单，成功后才删除被替代文件；失败保留旧清单和全部旧文件。用户编辑的 `seamTrimPixels` 不承担采集裁剪。新增屏数额度只计算实际新增行，替换旧行不额外消耗；部分接收或恰达配额时保持原默认缝与原跳过行语义。用户编辑存在、手动路径没有 full source、边缘不足或读取失败同样回退默认。调用者持有的正文／边缘／编辑清单与磁盘 published 输出不一致时，事务直接抛出 `invalidManifest` 并保持较新的输出完整；不能仅停用选址后继续发布过期 snapshot。

接缝 patch 转换复用线程安全的 `CIContext` 渲染资源，设置 `cacheIntermediates=false`，不保存来源帧或整幅输出像素。原生 ON／OFF trace 分别记录 ingest 与 commit 耗时，用相同输入衡量实际新增读取、转换、选址和编码成本；Debug 模拟器计时不等于真机预算，不能仅凭复用设计宣布提速。

`CaptureDiagnostics.seams` 由成功的仓库事务记录：默认／实际位置、替换行数、综合评分、方向与原因。位置是各次来源帧的原图行，不是会随后续 prepend 改变的最终长图坐标。保留最近 32 处明细，并记录总数、调整数和省略数；nil 的旧记录可直接读取，未提交的计划不得显示为已应用。中英文详情显示该坐标口径与截断数量。摘要与查看按钮位于捕捉详情 DisclosureGroup 外，作为独立可访问控件；明细使用独立可滚动列表和关闭按钮；“接缝评分”明确是综合像素差异与结构、越低越好，并说明保留默认的原因。编辑器 200 行余量及拖动接缝不在本轮实施范围。

详情 UI 曾出现“查看接缝明细”文字实际可见，却不能作为独立无障碍按钮被 XCTest 点按的问题。将摘要与带至少 44 点触控区的按钮移出 DisclosureGroup 后，中英文同一 UI 用例通过：32 条明细可滚到底，关闭后预览与保存按钮仍可访问，系统分享可真实打开并关闭；证据 `.work/beta6-validation/seam-details-ui-retry.xcresult`。此用例不证明真实选缝质量或照片写入结果。

新原生回归用 1179×2556 程序玻璃页面经过生产 CI、pipeline、事务和 PNG，按独立文档坐标与实际选择的来源帧行构造完整像素 oracle；配额、caps、反转、小条带和失败回滚另测。模拟器使用相同真实截图分别运行选址 ON／OFF，以 UIKit 实际坐标和卡片矩形核对缝的位置。当前实际通过状态与真机边界见 [0.1.5 发布记录](release/0.1.5-testflight.md)，不得用核心 217 项通过代替上述链路验收。

## 连续性与真实使用边界

- 系统未采集的中间内容无法还原。每次扩展都必须与保留的可信参考存在足够重叠；即便目标位置以前拍到过，参考已淘汰且当前无法重新定位，也必须拒绝。沿连续小步回到较早区域仍可恢复，并继续向任一端扩展。
- 当前模型估计一组正文的纵向位移，允许壁纸固定；不处理缩放、旋转、横向拖动、多块正文独立滚动或整页重排。重复消息、等距表格、低对比度渐变和大片无纹理区域可能无法唯一定位。
- 小范围加载和动画测试通过不等于通用动画支持。已保存正文不会因后续图片加载而回头更新；重叠区能对齐也不保证新增条带中的动画、浮层或滚动条会自动消失。
- 当前动态夹具刻意把加载补丁和细滚动条放在重叠区，以便对新增条带使用独立的干净文档真值。它们不证明整个截图都能去除这些动态元素。
- 微信朋友圈停留数秒、图片异步加载再滚动，是必须单独验收的实际场景。合成字形、图文纹理和暂停序列只能验证相应算法性质，不能宣称复现了真实朋友圈全部渲染行为。
- 有限灰度历史约束核心参考内存，但原始彩色帧、图像编码、首次条带提交和导出仍有各自峰值。Mac 上的匹配计时不能替代 ReplayKit 扩展内存、iPhone 延迟、耗电或温升测试。

## 本地回归验证

在仓库根目录使用项目脚本选择当前进程的 Xcode，不修改全局 `xcode-select`：

```sh
source scripts/xcode-env.sh
swift test --scratch-path .work/core-v2-build
swift run -c release --scratch-path .work/core-v2-build ScrollCaptureBenchmark --output .work/core-v2-benchmark
```

`StreamStitcherTests` 保留基础的重复帧、奇数位移、固定裁剪、回退、重叠边界、局部变化、非法输入和原始行高回归；`BidirectionalStitcherTests` 使用预先生成的独立文档覆盖向上起步、两端反复穿越、参考淘汰、单行扩展、稀疏文字、图文加载、停顿和保守拒绝。双向轨迹用例每一步输出都与预期文档区间逐像素比较，真值边界不取自算法返回值。

`FixedRegionDetectorTests` 另验证双向边界、留白、时钟变化、搜索边缘及无纹理拒绝；iOS 的 pipeline、存储、真实布局测试则负责彩色像素转换、自动首尾保留、提交原子性和失败恢复。它们的最终数量和执行结果独立记录，不能与核心合成基准互换。

0.1.4 新增 `HeaderCaptureAcceptanceTests`：1179×2556 与 886×1920 同色固定栏合成画面，经真实生产 Core Image 灰度转换、pipeline、仓库事务提交和 PNG 导出，使用预先定义的完整文档坐标与上下端原始固定栏逐像素核对。胶囊第二帧出现后连续向上六步、胶囊首帧存在随后消失的向下变体、时钟变化、手动范围、前景豁免与旧诊断语义分别覆盖。固定栏插入正文条带时，总高度仍可能正确，因此“高度相同”与“消息看起来有序”都不能代替完整像素真值。新增测试的实际运行状态见 [0.1.4 验收流程](validation/beta-5-acceptance.md) 与 [更新记录](release/0.1.4-testflight.md)，不能用此前原型结果代替。

固定壁纸另有两层独立验收：`WallpaperAcceptanceTests` 在 886×1920、1179×2556 的合成前景文档上核对全部不透明像素；`ScrollCaptureSimulatorCapture` 方案在真实 `UIScrollView` 中执行手势并取得系统截图，经过生产转换、拼接和 PNG 导出。后者用 UIKit 实际布局及滚动坐标作真值，测试编号只保存在元数据中，不作为可见匹配特征。此路径明确是模拟器截图注入，不运行真实 ReplayKit 广播。结果见 [0.1.3 更新记录](release/0.1.3-testflight.md)。

以上是本地必要验证，不要求新增 CI、自动发布或将测试流程作为日常 TestFlight 分发前置条件。

## 217 项确定性合成基准

当前 CLI 的报告格式和夹具版本均为 2，共 217 项、8,776 帧：

| 分组 | 数量 | 覆盖 |
| --- | ---: | --- |
| 常规组合 | 168 | 纹理、文字、聊天气泡、表格、分节、混合卡片、稀疏文字 7 类画布 × 5 / 10 / 20 屏深度 × 8 种轨迹 |
| 拒绝与恢复组合 | 45 | 周期歧义、断层后恢复、新场景、尺寸变化、重叠不足、低对比度歧义，以及向上的断层恢复、重叠不足和周期歧义，各 5 个变体 |
| 原始行高组合 | 4 | 144×2,556 正文分析区域的纹理、文字、混合卡片和稀疏文字；含暂停、双向运动、有限加载变化及细滚动条 |

8 种常规轨迹包括匀速、奇数步长、固定栏、短回退、暂停与回退、向上起步、向上暂停回退、两端穿越。算法接收不到画布生成器的文档位置、类型或种子。

验证器先独立生成画布和真实视口位置，再按算法返回的行范围及插入方向组装输出。每帧均与真实位置确定的完整文档区间逐像素比较，并核对状态、当前偏移、最早与最远边界、插入方向、行范围和拒绝原因。最终输出不是只与从零开始的前缀比较，也不是仅检查算法自身的内部计数。

输出目录包含 `report.json` 和 `report.md`。JSON 记录种子、尺寸、裁剪、配置阈值、每帧预期与实际结果、像素一致性、置信度、耗时及失败明细。完整输出的 FNV-1a 64 位指纹用于复核；通过条件仍是实际像素数组相等。

预期歧义或断层的安全拒绝属于压力用例通过条件。分类 `complete` 表示该序列无拒绝，`rejected` 表示至少一次非歧义拒绝，`ambiguous` 表示至少一次歧义拒绝；分类不是产品质量评分。CLI 全部通过返回 0，出现测试差异返回 1，参数或运行异常返回 2。

2026-09-14 的本地 Release 运行结果为 **217 / 217 通过，8,776 帧每帧像素一致**。总耗时约 30.6 秒，其中核心匹配约 27.4 秒；总耗时包含夹具生成与验证，不含编译和报告写入。
