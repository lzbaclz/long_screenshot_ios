# 流式长截图对齐核心

状态：首版实现与合成数据测试完成。本文不代表微信、信息流、真实字体缩放、ReplayKit 实机采集或性能门槛已通过。

## 输入与输出

`ScrollCaptureCore` 是独立 Swift Package，仅依赖 Foundation，可在 macOS 使用 Swift 6 测试。iOS 捕捉层将画面缩小并转为紧密排列的 8 位灰度数组，原始彩色画面由捕捉层另行保留。

```swift
let configuration = AlignmentConfiguration(topInset: 18, bottomInset: 24)
var stitcher = StreamStitcher(configuration: configuration)
let frame = try GrayFrame(width: width, height: height, pixels: grayscale)
let result = stitcher.ingest(frame)
if let rows = result.sourceRows {
    // rows 属于本次输入帧坐标。捕捉层换算到原始分辨率后写入新增条带。
}
```

灰度输入的顶部和底部裁剪量必须与输入分辨率一致。首帧输出整个裁剪区域；之后仅输出超过历史最远位置的底部新内容。`sourceRows == nil` 时不得写入条带。

| `status` | 语义 | 输出条带 |
| --- | --- | --- |
| `started` | 首帧建立原点 | 整个裁剪区域 |
| `advanced` | 画面超出此前捕捉到的最远位置 | 未见过的底部行 |
| `unchanged` | 与上一可信位置相同 | 无 |
| `backtracked` | 移动到已经捕捉的范围内，包括回退后再往前移动 | 无 |
| `rejected` | 缺少可信重叠、位置存在歧义、尺寸变化或配置错误 | 无；保持此前状态 |

`contentOffset` 表示当前可信画面相对首帧的位置，`furthestOffset` 保留历史最远位置。向首帧之前滚动可以产生负偏移，但首版不会向结果头部补图。

## 对齐方法

1. 先排除用户配置的固定顶栏和底栏。裁剪区域完全相同则直接报告静止，避免在空白或周期内容中推测不可见滚动。
2. 对最近可信画面逐一搜索正、负整数纵向位移。默认至少保留 40% 的重叠区域。
3. 粗评估使用较稀疏的空间采样，但不跳过整个位移候选，保证锐利文字的奇数像素位移也能命中。
4. 每个参考画面保留误差最小的 12 个候选，以更多行、列重新评估。误差结合完整均值和去掉最高 15% 行误差后的均值，降低局部动画或加载行的影响。
5. 比较最佳位置与其他位置，即使只相差 1 行也作为不同解释。默认误差需不超过 15，且相对第二种位置解释有至少 2 的误差优势。多个参考画面对同一绝对位置的支持合并看待。
6. 仅在可信时更新位置，并保存最多 `maxHistory` 张参考帧。默认 3 张，配置上限 8 张。失败输入不会替换可信参考。

`confidence` 是由匹配误差和候选分离程度组合得到的 0 至 1 启发式分数，不是经过真实数据校准的成功概率。未知大跨度不会直接上下拼接；用户回到已捕捉区域恢复重叠后，可以继续采集。

## 明确边界

- 系统没有采集到的中间内容无法还原。滚动超过重叠限制会拒绝；持续无法恢复时，捕捉层应结束并保留已有部分。
- 重复表格、等距相似消息、空白区和周期图片可能无法确定位置，算法倾向拒绝或维持已有内容。完全相同的可见画面无法证明发生了隐藏滚动。
- 首版只估计纵向平移，不处理缩放、旋转、横向拖动、多区域独立滚动、页面内容整体重排或超过历史窗口的回跳。
- 默认在首次可信滚动时保守推断固定栏；边界不明确时要求手动指定区域。非零手动裁剪值直接覆盖自动检测。透明渐变栏、动态栏和留白不保证自动识别。
- 小范围动态内容的测试通过不代表动画通用支持。已经保存的内容不会回头更新；广告和异步图片仍可能需要重试或手工处理。
- 如果纵向也缩小灰度图，位置会有分析像素量化误差。捕捉层宜仅缩小横向、保留原始行高，或者加入原始分辨率接缝校正；接缝精度仍须实机验证。
- 内存只保留有限参考帧，不保留整段视频。总内存和原图导出峰值由捕捉、持久化和导出层共同决定。

## 默认固定区域检测

`StreamStitcher` 本身仍只执行给定区域的对齐。iOS `CaptureFramePipeline` 在用户上下忽略比例都为零时启用 `FixedRegionDetector`；任何非零手动值都明确覆盖自动判断。

尚未写入条带时，先在中央 60% 画面估计向下位移。接着逐行比较画面边缘的“原位置不变”与“随正文平移”两种解释，要求固定区域末行有明确静止证据、紧邻正文有明确移动证据，每端最多检查画面高度的 30%。解析后的候选首帧与当前帧会重新送入最终裁剪区域的对齐器，只有位移再次一致才写入完整首段和新增正文。

有效上下边界通过 `effectiveConfiguration` 提供给采集层，长度上限按实际正文高度计算。检测不可靠时返回 `regionWarning`、不提交任何首段，采集层结束并提示用户手动设置忽略区域。白色固定栏与白色正文留白有时无法从两帧中区分，因此宁可拒绝，也不擅自删掉正文。纯色边缘、半透明或动态栏、过大的初始滑动仍可能需要手动设置；已经开始后的固定栏布局变化不重新自动裁剪。

首次中央探测需要至少 40% 中央区域重叠，相当于首个向下位移不超过全帧高度约 36%。这是用于避免错误起点的保守限制，不是已完成的全应用通用识别。下述 120 项合成基准直接运行指定区域的核心对齐，不作为自动固定栏成功率证据。

## 可复现合成基准 CLI

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift run -c release ScrollCaptureBenchmark --output .work/core-benchmark
```

CLI 执行 120 项确定性灰度夹具：

- 90 项常规组合：纹理、仿文章、聊天气泡、表格、分节和混合卡片 6 类画布，各自运行 5 / 10 / 20 屏深度与匀速、奇数步长、固定栏、短回退、暂停与回退等 5 种轨迹。
- 30 项压力组合：周期内容歧义、断层后恢复、新场景、尺寸变化、低于最小重叠、低对比度歧义，各 5 组尺寸或种子变体。

画布先由固定种子生成，再据真实滚动位置取帧。验证器将算法要求保留的行写入输出，并与独立画布前缀逐像素比较，同时检查每帧的预期行数、绝对位置、结果类型和拒绝原因。测试结果不由算法自身的位移推导真值。算法接收不到生成器的文档位置、类型或种子。

输出目录包含 `report.json` 与 `report.md`。JSON 记录夹具版本、用例编号、种子、尺寸、裁剪、周期参数、重叠和误差阈值、每帧预期/实际行范围、结果类型、拒绝原因、置信度、时间、完整输出的 FNV-1a 64 位指纹及失败明细。指纹用于方便复核，最终通过条件仍是实际像素数组相等。Markdown 提供 120 项结果表。

预期歧义或断层的安全拒绝算作对应压力用例通过。分类 `complete` 表示序列无拒绝，`rejected` 表示至少一次非歧义拒绝（可能随后恢复），`ambiguous` 表示至少一次歧义拒绝。CLI 在全部通过时返回 0，存在测试差异时返回 1，参数或运行异常返回 2。

夹具版本相同时，种子、帧位置、真值像素及结果应可复现；生成时间与性能计时会变化。首次本机 Release 运行完成 3,730 帧约需 5 秒，不含编译。该数字仅供安排本地验证，不能代替 iPhone 性能验证。

这些是受控参数组合，不是独立真实样本，不能用 120 项的通过比例估计产品成功率，也不能把它们计入计划书的 G1 真机验收或 20 人内测指标。
