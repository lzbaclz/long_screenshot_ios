# 续页 / Longlet 0.1.3（4）固定壁纸聊天修复

日期：2026-09-14。**0.1.3（4）已开放内部 TestFlight，原测试组显示“正在测试 / 90 天后过期”。** 上传于 13:35:29 Europe/London 成功，Apple 处理完成；测试说明已保存中英文内容。

## 本次反馈与原因

用户继续反馈进入聊天后滚动仍只留下接近单屏的结果。提供的诊断为处理 38 帧、衔接 1 帧、未衔接 25 帧、恢复 1 次，最终收到系统暂停，单帧处理峰值 390 毫秒。诊断页显示 886×1921，而另一个结果附件的实际尺寸为 886×1963；不把它们混同为同一份像素证据，也不能据此断言只增加了某一行数。

新证据是聊天的照片壁纸固定在屏幕上，文字气泡、头像和图片卡片独立移动。之前的纯色聊天、整幅页面平移和短中文测试没有覆盖这个双层画面。固定壁纸的纹理会干扰全幅位移评分，使真正的滚动被拒绝。用完全程序生成的同类画面已复现这一问题；没有将用户私人截图或聊天加入仓库和自动化夹具。

另外，旧扩展在 `broadcastPaused()` 内直接终止并调用 `finishBroadcastWithError`，把可恢复的暂停变成了主动结束。用户截图只能证明收到了暂停回调，不能证明 iOS 发起暂停的具体原因，也不能用这一回调解释此前所有匹配失败。

## 修复方法与用户可见变化

1. 区分固定的纹理背景和移动的消息，在发生变化的局部寻找字形、气泡和图卡特征。先用特征提出有限的位移候选，再验证双向局部误差、支持分布和替代解释。重复头像或单个动画不能独自决定整页滚动。壁纸被大气泡遮挡时，仍依据分布充分的静止纹理判断，避免把背景占比作为错误前提。
2. 向更早内容滚动时把新条带接到顶部，向更晚内容滚动时接到底部，回到已有范围不重复添加。自动启动也使用前景证据，并在最终匹配区域重放确认；失败的移动帧不会直接替换起点。
3. 系统暂停时保存记录、保留有限的可信参考并暂停计时。恢复后先验证与暂停前的重叠，再继续拼接；未知间隔不直接跨接。系统结束和暂停分别记录，终结操作只执行一次。
4. 捕捉详情增加暂停／恢复计数和最慢阶段峰值，便于区分匹配、图像生成和写入耗时。记录仅保留本地数值统计，旧记录的新增字段可为空。

每周免费导出 50 个新作品的口径与历史计数保留规则延续。没有添加自动 CI 或自动发布流程。

## 验收设计与过程

模拟器使用真正的透明 `UIScrollView`，在固定程序纹理壁纸上显示 64 条合成中文消息，混合白／绿气泡、短句、重复头像、时间签和图片。XCTest 执行真实拖动，取得系统截图，然后注入生产灰度转换、拼接、存储和 PNG 导出链路。页面的实际 `contentOffset` 与布局矩形是独立真值，不读取算法输出位置来修正期望。

最后一轮移除了全部可见测试编号，消息 ID 仅用于 UIKit 元数据和验收记录，算法输入中没有人工编号。检查范围包括直接向早期滚动、直接向后滚动和两次反转。最终高度必须等于真实覆盖范围，并逐条核对完整消息的内部像素与自然顺序。另有 886×1920、1179×2556 的独立原生绘制夹具，严格核对覆盖区域全部不透明前景像素。

初轮集成验收曾实际失败：真实滚动应得到 7072 像素高，输出只有 3067；第一段成功后其余被拒绝。该记录为开发中代码，不冒充精确的已发布版本回放。后续直接重放同一批 144×2622 灰度帧，发现气泡遮挡使静止纹理比例只有约 23%–25%，尽管有数千个分布充分的稳定点，旧 30% 门槛仍错误排除了前景匹配。

## 验证边界

- 模拟器的真实拖动与截图注入不等于 ReplayKit 跨应用真机捕捉；暂停／恢复的本地状态测试也不等于已经观察到手机系统的全部回调顺序。
- 固定壁纸与滚动消息不能同时形成一张全局平移的原图。输出保留原始图片条带，优先保证消息完整及顺序；壁纸可能出现接缝，不会重画背景或修改用户照片。
- Mac 核心计时和模拟器耗时不能替代手机广播扩展的内存、温度与耗时测量。本轮新增阶段统计用于后续依据实际数据继续排查。
- 缺少真实重叠、完全重复内容、缩放／横向移动或大范围异步重排仍可能无法可靠定位；不能编造未采集的中间消息。
