# App 资源库长图接缝穿过半透明文件夹：诊断与修复设计

日期：2026-09-15。依据用户在 0.1.4（5）上的真机反馈：微信聊天上滑长图正常；iPhone App 资源库（用户称“负一屏”）的长图在“娱乐／旅游”一行有明显瑕疵。本文记录从导出图本身能确认的事实、原因判断、修复设计与验证边界。用户导出图与原生截图只在本机分析，未复制进仓库或测试夹具。

## 现象

导出图 884×2380，只比一帧（884×1920）多 460 行。自上而下：状态栏与顶部毛玻璃（下面透出被盖住的“建议／最近添加”文件夹）、搜索栏、“建议／最近添加”标签、“社交／创意”一行、“娱乐／旅游”一行、“效率／工具”、“信息与阅读／购物与美食”及不完整的最后一行。用户圈出“娱乐／旅游”：两个文件夹顶部有一条横向断线，文件夹顶边看起来像被切平，背景亮带在同一高度戛然而止。

## 已确认的事实

分析脚本与结果在 `.work/app-library-seam-investigation/`（`analyze.py`、`analysis.log`、`compare_row.png`、`zoom_yule.png`）。

1. **主要图标布局支持大致一致的位移解释，不能证明全图无丢失或重复。** 导出图与原生截图缩放同宽后，按 60 行窗口做归一化互相关，高相关区段的最佳偏移主要在 +335 到 +337，相关系数约 0.82–0.98；部分窗口只有约 0.60–0.67，且出现错误对应。文件夹、图标的主要尺寸与间距大致一致，跨明显断线仍有相近偏移，但这些局部相关结果不等于逐像素完整性验证。
2. **第 847 行有一条显著背景跃迁，不能据此确认实际只提交过一次接缝。** 中央背景列在该行的灰度跳变约 34.9；搜索栏自身第 231–256 行另有玻璃边缘。`387 行顶部 + 460 行新增 + 1533 行起始正文 = 2380` 与一次向上扩展的输出结构相容，但缺少原始采集帧与当时详情，387 行匹配上界、一次扩展和条带分解仍是结构推断。
3. **接缝正好落在文件夹顶部带内。** “娱乐／旅游”文件夹顶边在第 822 行左右，图标在第 850 行开始，接缝穿过 822–850 之间的玻璃边框。

## 原因判断与证据边界

App 资源库的背景是固定不动的模糊壁纸，文件夹是 iOS 26 的半透明玻璃，会透出并折射背景；只有文件夹和图标随手指滚动。两帧在接缝处来自不同滚动位置，背景不可能连续。这与微信壁纸聊天的“壁纸接缝”是同一类限制（[算法说明](algorithm.md)“固定壁纸与移动消息”），差别在于聊天气泡不透明，接缝只出现在气泡之间；玻璃文件夹把背景差异带进了文件夹内部，于是看起来像文件夹被切开。

接缝位置由现有规则决定：向上扩展时，新条带固定取当前帧匹配区域上边界以下的新增行，接缝对应旧正文的匹配上边界。按本图结构推断，该上边界约为第 387 行、位于文件夹顶边下方约 25 行，但这不是从原始帧或清单读出的已证数值。规则没有考虑接缝落在什么内容上。

顶部毛玻璃覆盖部分文件夹的画面，与系统滚动状态下的渲染相容；按产品契约，头部取自最早已捕捉位置。仅凭导出图不能确认当时是否回到页面最顶端，也不能把这部分遮盖全部归因于拼接。

## 初始修复设计（历史提议，正式契约见实施补记）

原则不变：只输出原始像素，不重画背景，不做跨帧混合，不放宽位移、误差与歧义门槛。改变的是“接缝切在哪一行”。以下 A／B 保留最初设计过程；±窗口、借固定边缘、复用编辑裁剪字段均未直接实施，正式实现已改为在真实保留正文的一侧做有界替换。

### A. 接缝选址（采集层，核心提供评分）

两帧重叠区通常有上千行，条带边界可以落在重叠区内任何一行。位移被信任后：

1. 在重叠区内、以默认接缝为中心的有限窗口（建议 ±min(240 行, 重叠高度的 35%)）逐行比较两帧对齐后的像素：整行平均绝对差 + 纵向梯度惩罚（避免切在图标边缘）。
2. 初始提议按差异选择接缝、同分时靠近默认位置。实施中的反例表明，原始平均绝对误差（MAE）最小处可能是不透明图标内部；空隙处 MAE 反而更高。因此不能声称“最小 MAE 必在空隙”或“选址后原始差异必下降”，正式评分改用共享结构占用和邻域平稳性筛选。整页完全一致或只有很小量化差异时保持默认。
3. 分层壁纸路径同样适用；前景评分已给出可信位移，选址只用对齐后的差异。

实现位置：`StreamStitcher` 已有对齐后的两帧，可在 `advanced` 决策里附带 `seamShift`（相对默认接缝的行数，含符号）；`CaptureFramePipeline` 据此扩大或缩小本帧条带，`CaptureSessionRepository.commit` 同事务调整相邻旧条带。核心 API 增加字段用默认值，旧调用不受影响。

### B. 相邻旧条带的调整规则（历史方案，未直接采用）

下列是最初的带符号方案：设向上扩展的位移为 d，默认接缝为旧帧匹配区域上边界，接缝位移 s（正值向下、负值向上）。其中借用 cap 的分支会把固定栏重新带入正文，`seamTrimPixels` 又属于用户编辑；二者均已被正式实现否决：

- s < 0：本帧条带取 `top ..< top + d + s`（更少），旧帧头部边缘的最后 −s 行保留为正文，其余头部边缘照常被新头部替换。旧帧头部边缘此时仍在盘上，无需重新采集。
- s > 0：本帧条带取 `top ..< top + d + s`（更多），旧帧紧邻条带从顶部裁掉 s 行；`seamTrimPixels` 已支持按条带裁顶。
- 向下扩展对称：s > 0 保留旧尾部边缘的前 s 行，s < 0 裁旧条带底部。
- |s| 不得超过窗口，也不得让任一条带高度归零；旧条带若已被更早提交裁过，只在剩余高度内裁。

同一事务内提交，失败仍回到上一份完整清单。输出覆盖范围、行序和总高度不变，只改变一段行来自哪一帧。

### C. 接缝余量与编辑（可选设想，本轮未做）

每个条带额外保存接缝一侧最多 200 行同帧余量，清单中标记为余量、默认不渲染。编辑器“拼缝微调”即可上下拖动接缝而不只是裁掉，供自动选址不理想时手动修正。磁盘占用有上界，导出不含余量。

### D. 诊断

捕捉详情记录每次接缝的默认位置、实际位置与选址差异分值，便于真机反馈时判断是选址问题还是位移问题。

## 目标用户可见变化（须以正式验收与真机复测确认）

- App 资源库、有壁纸的聊天等固定背景页面，接缝会尽量落在内容之间的平稳空隙，减少文件夹和气泡内部的横向断线；背景本身仍可能在空隙处不连续。
- 普通页面看不出变化。
- 可选的接缝余量上线后，编辑器可以上下拖动接缝。

## 验证边界

- 本文结论来自导出图与原生截图的比对，没有该次捕捉的原始帧与详情记录；“向上翻页、一条接缝”是从图片结构推断的。如需确认，可查看这条记录的捕捉详情中的匹配区域数值。
- 导出图只新增 460 行。若实际滚动距离远大于已增加的范围，可能有后续帧被拒绝或未进入连续输出；图像本身不能确定原因，属于另一个待诊断问题（固定模糊背景缺少二维纹理、玻璃文件夹随位置折射），需要该记录的拒绝帧计数与最后阶段才能判断。
- 选址只能减少接缝的可见性，不能消除固定背景的不连续；不做跨帧混合。
- 本方案不改变头部边缘取自最早已接收位置帧的规则，也不清除系统真实覆盖层。

## 2026-09-15 最终实施设计

以下为当前生产契约；前面的初始设计保留为调查历史。版本目标为 0.1.5（6），实际发布状态见 [更新记录](release/0.1.5-testflight.md)，不以原型或中间构建结果代替最终验收。

### 两个独立的匹配问题

**候选提出遗漏。** 首轮原生上滑反转的选址 ON／OFF 同为 3091 行，独立期望 2964；真实新增 102 行被旧匹配器判成 229，caps 仍为 265／270。精确 HEAD 核心重放同一灰度可复现。夹具每 127 行重复图标，真位移只有 2 票而被原 top-8 截断，假位移获 8 票。原验证器校验真实位移的误差为 2.44，优于假位移 7.55。

主 agent 明确扩大范围修复候选提出，原夹具、2964 独立期望和 ON／OFF 对照保留。正式策略保留原 top-8 全部 ±1 候选，再补最多 8 个相互分散的票数峰，最多 48 次原校验。没有放宽误差／歧义门槛，也没有把 102／127 写入生产规则。隔离同帧对照中 top-16 用 30 个候选，分散补充用 24 个，均恢复 -102；Mac 热测中位约 11.64／11.48 毫秒，原 top-8 为 11.56，差异在调度噪声范围，不代表真机性能。证据 `.work/beta6-validation/legacy-alias/diagnosis.md`。

**固定层证据范围不足。** 四条真实 UIKit 路线在完整允许范围内能识别真前景位移，但缩窄 ROI 后固定纹理支持不足，先退回 `notLayered`，发生在投票之前，增加峰数不能解决。`stationaryEvidenceRows` 将静止纹理证据范围与运动 ROI 显式分开，默认仍为同一 ROI。Shared 仅在自动且明确 foreground 的重放器中传原允许范围；每一帧对重新证明固定层，运动特征、验证和重叠仍限正文，manual 不扩范围，无 sticky 放行，也不把固定栏当成运动证据。四条同原始灰度的隔离重放恢复每步真实 ±450；完整 UIKit PNG 另由主 agent 验收。证据 `.work/beta6-validation/glass-readonly-replay/diagnosis.md`。

### 实际输出边缘与单侧替换

选址位于 `CaptureSessionRepository.commit` 的 `.advanced` 正文事务中，位移已经被 pipeline 接受。旧 patch 从 `updated.strips` 真正保留的正文边缘读取，可横跨多个小条带及此前裁过的 immutable 条带，排除 leading／trailing caps。首次事务前面刚编码的 initial body 也可参与。最新匹配参考在反转或历史淘汰后可能不在输出边界，不能替代实际旧像素。

`SeamSelector.select(retained:incoming:direction:overlapLength:maximumShift:)` 接收同一文档区间的两个灰度 patch，不估计位移。`s >= 0`，不超过 480 原图行、真实可用重叠的 35% 及已加载区域的安全上限。只加载最多 486 行（搜索区加 6 行上下文），真实重叠长度另传。没有全帧历史缓存或整幅长图复合缓存。

- prepend：新条带向下多取 s 行，旧正文头部移除 s 行。
- append：新条带向上多取 s 行，旧正文尾部移除 s 行。
- 可整条移除耗尽的小 strip；余条裁为新 ID 的 immutable PNG，不留下零高度文件，不使用用户 `seamTrimPixels`。cap 沿用 Beta 5 原始首尾各保留一份的契约，不借其像素当正文。

每次只改变确认文档行的像素来源，事务检查正文高度严格增加 admitted rows，替换旧行不额外消耗屏数额度。部分配额接收或恰达上限保持默认接缝及原 prepend／append 跳过行语义。有用户编辑、没有原始 seam source（包括现有 manual 路径）、边缘不足或读取失败时保持默认。传入清单若与磁盘较新正文／编辑不一致则是写入冲突：新文件写入前抛出 `invalidManifest`，不能以旧 snapshot 覆盖新结果。

所有新图像与余条先写盘，再原子发布清单；成功后才删被替代旧文件。任一编码、后续条带或发布失败，旧清单与旧文件完整，临时文件清理，未应用的计划不能记入已发布诊断。内部 ON／OFF 开关只用于同输入验收，不增加用户设置。

### 最终接缝评分与弱玻璃结构

综合代价使用像素 MAE、横向结构占用和邻行活动。空隙的原始 MAE 可能比不透明图标内部更高，不能按最小 MAE 选缝。完全一致、默认已平稳、量化级差异、收益不足或没有安全候选时保持默认。

亮／暗真实截图重放暴露两处暗玻璃漏检：卡片内部图标之间的玻璃空白，边缘低于原 8 级阈值，被当作平稳空隙。最终保留强一阶差 `>=8`；补充**同一帧**一阶差 `>=3` 且二阶差 `>=3` 的弱结构，再对两帧取 OR。二阶差为 `abs(2*center-left-right)`，不能组合 A 帧坡度与 B 帧噪声曲率。原 6 行邻域、2% 结构占用、纵向平稳、评分权重和收益门不变。不采用绝对亮度自适应；对反相和未裁断的亮度平移保持一致，±1 量化噪声不触发弱边缘。

按实际新 shift 连续裁旧正文、插新条带并更新下一步 frontier 的 40 次灰度重放中，32 次实际调整全在独立卡片矩形外，8 次本来平稳的默认保持；最终同帧条件调整前后这些 shift／score 一致。该链式重放不能替代实际 iOS PNG 验收，证据 `.work/beta6-validation/glass-seam-replay/diagnosis.md`。

来源 oracle 同时检查独立文档坐标和原始像素。固定背景可能在多个视口相同屏幕行逐字节相等，因此不能先随便选首个像素匹配再判断坐标；必须找到同时满足原 ±2 像素坐标容差与逐字节相等的来源，且再次确认实际 UIKit 视口范围，未放宽容差或删除像素条件。

### 诊断与实际 UI 修复

仓库仅对成功正文事务记录默认／实际来源帧行、实际替换行数、接缝评分、方向和原因。位置属于各次 incoming 帧的原始图像行，不是最终长图坐标；后续 prepend 会移动旧接缝在输出中的位置。适配器刷新其他统计时保留仓库字段，未提交计划不算 applied。旧 schema-1 无字段仍兼容。

最多保留最近 32 处明细，另记总数、调整数与省略数；“接缝评分”说明综合像素差异与结构、越低越好。原 UI 的查看文字在屏幕中部可见，但嵌在 DisclosureGroup 内时无法作为独立 AX 按钮点按。摘要和带至少 44 点触控区的查看按钮现移到 DisclosureGroup 外，明细用独立可滚动 List，提供明确关闭与本地化原因。

`.work/beta6-validation/seam-details-ui-retry.xcresult` 中 1 / 1 用例通过，包含中英文两个循环、32 条滚到底、关闭后预览及保存按钮可访问、系统分享真实打开关闭。演示数字仅由 DEBUG 的显式 demo／uitesting 参数注入隔离库，不表示执行了 40 次真实选址；该用例也不证明照片写入。本轮未做 200 行编辑余量或拖动接缝。
