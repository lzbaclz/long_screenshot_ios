# 第二版内测修复与验收

日期：2026-09-14。用户要求：向上扩展长图、测试免费导出 50 次、解决频繁截图失败。实现交给指定的 GPT-6-Astra / xhigh 子 agent，主 agent 独立验收。CI 保持仅手动触发。

## 已确认事实

- 用户截图显示测试版仍为 3 / 3 导出额度；源码只有验证到沙盒收据后才为 Release 开放无限，无法保证实际测试用户得到预期额度。
- 用户截图有多条 0 × 0 记录，却显示“部分内容已保留”。这不表示成功保存了画面。
- 当前拼接器能定位负向位移，但不把起点上方的新内容接入输出。首次采集还会将反向滚动视作候选起点变化。
- 固定区域识别对留白、动态状态栏和精确边界要求过严，区域不确定会立即结束广播。其他无法匹配帧仅允许短暂恢复。
- 截图没有提供失败时的屏幕帧或扩展日志，因此具体微信失败原因仍需验证；不能把上述代码问题直接当作全部真机根因。

## 实现方案

### 双向连续内容

跟踪已捕捉的上、下边界。从顶部扩展时插入新头部，从底部扩展时追加新尾部。已覆盖范围内来回移动不重复；最终按页面阅读顺序排列。拒绝跨越没有可靠重叠的缺口。

### 默认采集可靠性

启动阶段允许系统界面、应用切换和短暂画面变化；用可信的运动、文字及多帧证据确认可拼接区域。白背景不能凭面积大小成为“匹配成功”的证据。空白、周期纹理、不同页面仍必须保守处理。

自动区域只用于内部接缝，输出保留最上端和最下端的原始边缘各一次；随新内容扩展原子替换对应边缘，避免精确边界不明时丢失正文。手动范围继续按用户明确设置裁剪。确实无法形成长图时，区分单屏结果与无图失败，不把两者算成长图成功。

检查生产帧转换和图片裁剪的上下方向是否一致。检查原图、灰度帧、PNG 编码与首段提交时的内存生命周期；不让新机制无界缓存全分辨率帧。

### 测试导出政策

用户已确认每周 50 个成功导出的新作品，按既有 ISO 周口径计数。政策明确写入测试版，不依赖网络或 TestFlight 收据。失败、取消和同一作品重复导出不扣次数；升级沿用已保存的成功记录，只计算当前周消耗。正式上架的商业政策后续再定。

用户补充失败发生在微信朋友圈：停留 3–5 秒后向下浏览，滑动一段后应用主动结束。需要特别检查图文动态加载、短暂匹配失败、静止计时与处理帧耗时；目前不能仅据返回主应用确定具体终止原因。

### 可理解的结果

无图记录显示失败及可理解原因；有一屏显示单屏；有连续长图才显示完成或部分已保留。历史记录保留，失败不能被统计为可恢复图片。界面、中英文引导与额度统一更新。

## 验收标准

| 场景 | 通过要求 |
| --- | --- |
| 从中间向更早内容扩展 | 起止范围正确、图片阅读顺序正确、无重复行 |
| 上下交替越过两端 | 仅新范围扩展，已覆盖范围内不增加长度 |
| 灰度与原图坐标 | 生产转换的已知行标与原图裁剪方向一致 |
| 白底文章、气泡聊天与留白 | 默认自动模式能保存真实连续长图；核对正文，而非仅检查没有报错 |
| 固定栏与动态状态栏 | 固定栏不在内部接缝重复，正文无静默裁掉 |
| 暂时无法匹配后返回 | 原可信画面保留，能恢复时继续，不跨未知缺口 |
| 页面切换、纯空白、周期纹理 | 不伪造连续长图；给出正确结果类别 |
| 首尾替换中断 / 写入错误 | 上一次原子保存的连续结果可恢复 |
| 长度上限 | 顶部与底部扩展都保留靠近已有接缝的正确区段 |
| 额度 49 / 50 / 51 | 第 50 个可成功导出，第 51 个新作品受限；重复导出不多扣 |
| 更新、重启、离线及失败 | 额度稳定，成功记录不重置，失败和取消不扣 |
| 旧 0 × 0 与旧作品 | 无图失败文案准确；旧作品仍可查看、编辑、导出 |

先跑有意义的核心及像素测试，再跑本地主应用、UI 与真实 Photos 拒绝路径；不用云端 CI 代替验收。不把合成夹具或模拟器通过写成微信真机已全部解决。用户通过更新的 TestFlight 继续提供真机结果。
